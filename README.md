# 辰江网络杂志 4.0.1

为家庭阅读准备的多源图文杂志：天下观察、军情与战史、百年中国、文娱故事。阅读先显示本机完整文章，再接收已准备好的新一期。

点击“换一批”立即轮换本机完整文章，优先未读、尽量避开上一批；刷新网页或重新打开也会轮换。首页每批最多 12 篇，四栏兼顾；栏目可轮换或查看全部。网络检查在后台进行，连续点击不会叠加请求。轮读完本机内容后会再次遇到旧稿，新增原文由后台定时补充。

在线阅读：https://chuhanchen.github.io/ 。2026-10-20 已完成首次发布和后续更新发布验证。

## 当前 Mac 试读

双击 `启动本机预览.command`，在浏览器打开 `http://127.0.0.1:18787/`。本机服务随终端关闭或电脑休眠而停止；它还不是手机和 Windows 的长期在线地址。

## 选稿规则

先判断内容是否适合，再考虑新旧、平台和图片能否完整处理。文娱选择人物经历、婚姻往事、影视幕后、音乐和作品解读。活动快讯、文旅推介和产业宣传不补进栏目；百年中国聚焦近现代叙事。天下优先分析评论，普通新闻在整期中至多约两成。文娱同一作者每期最多三篇。

持续发现入口包括 360 首页、头条热榜、观察者网、凤凰频道、搜狐频道和作者公开主页。头条热榜只用于发现话题，找到相符的完整原文后才标注关联；不宣称获得头条个性化首页。`service/reading-shelf.json` 仅保留首期口味校准参考，已退出持续发现来源，不参与人物补稿和额外加权。刀郎、迟重瑞等只是举例，不是每期必选名单。后续按人物往事、影视幕后、音乐故事和作者解读等内容类型选稿。

标题、作者、原始日期和配图顺序保留，不用模型生成正文或续写。旧文章不会伪装成刚发生的消息。选稿分类采用可检查的规则，仍可能误判；来源内容并不等于逐条事实核验。公开页面只有片段、配图无法完整处理或请求失败时，整篇不发布。

## 运行和验证

需要 Node.js 22 以上，推荐 24。

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run collect
node service/export-seed.js
npm start
npm run export
```

默认端口 8787。可设置 `PORT=18787`；只有设置 `CJ_AUTO_COLLECT=1` 才启用独立进程定时准备内容。每轮有时间上限，失败保留上一期。阅读请求不抓取来源网页。封面宽度至多 720，正文图片至多 1280，保持比例；原图出处存于数据中。

首期内置完整图文。浏览器缓存已打开页面和图片；尚未下载的新图不能离线显示。收藏与阅读记录保存在本机，不上传。

## 长期更新与安装包

已准备 GitHub Actions + GitHub Pages 流程 `.github/workflows/pages.yml`，用于公开仓库、每两小时尝试准备并发布静态内容。不需要常驻服务器或 Cloudflare 账号。定时准备是普通程序，不调用大模型 API，不消耗对话额度。公开仓库及 Pages 已配置，服务器已多次成功完成内容准备与发布；三端预设同一内容地址。定时任务可能延迟。程序只在目录确有变化时提交文章目录，记录实际更新；若来源长期不更新，仍需关注工作流状态。

安卓、Win7 与 Win10 的打包代码位于 `native/`。内置 24 篇完整图文，先显示本机内容，再从已配置的地址接收新一期。联网更新后仍优先使用内置图片，避免内置图文因断网丢图。Win7 使用 Electron 22 兼容引擎，Windows 真机兼容性仍需实测。旧 U 盘安装包未替换。

自动测试覆盖正文边界、公开正文及图片解码、文旅宣传排除、人物及评论入选、来源分散、离线缓存、阅读接口不触发采集、路径限制与原子更新。浏览器检查覆盖桌面和手机宽度；本机速度不代表实际手机或 Windows 的速度。

交付时验证：16 项自动检查通过，包含示例书架不进入持续发现且不额外加权、离线立即换批、未读优先及并发更新限制；安卓 Android 14 模拟器已安装、断网启动并从线上接收过 41 篇；Windows 更新模块已读取线上内容并命中离线图片缓存。示例规则调整后发布的一期为 35 篇，其中文娱 9 篇、普通新闻 7 篇。Electron 22/44 公共阅读界面已在当前 Mac 检查，Windows 真机和 vivo X50 真机尚未验证。
